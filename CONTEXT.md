# NiftyFix: handoff context for agents

Read this first. It is the single page an agent needs to continue building NiftyFix's tools. Last updated 5 November 2026.

## 1. What NiftyFix is

- **Live site:** https://niftyfix.in, an India-first, free, browser-only file tools site ("get your files ready for any upload").
- **Privacy model:** files never leave the user's device.
- **Owner:** Prasad Bhalerao, Maharashtra (GitHub `prasadbhalerao1`, public contact prasadbhalerao279@gmail.com).
- **Repo:** private, `prasadbhalerao1/Tools`, branch `main`. CI must be green.
- **Status:** 25 tools are built (2 form tools, 16 PDF tools, 7 image tools), plus 26 search-intent pages (63 URLs in the sitemap). About 395 more are planned. Image tools added on 5 Nov 2026 are committed; check whether they are deployed (`curl -s https://niftyfix.in/image/compress-image/`).

## 2. Owner rules (non-negotiable)

1. **No em dashes anywhere** (the U+2014 character): in code, copy, docs or commits. Use a colon, comma or full stop. `pnpm check:tools` fails the build if one appears in apps, packages, tools, scripts or e2e.
2. **Colours:** no blue, purple, violet, pink or navy, and no "AI slop" gradients. Use warm stone neutrals with orange (`brand`) as the only accent. Dark mode is the default; light mode is cream, not white.
3. **Speed is a product requirement.** The site must be smooth on low-end phones and slow 3G. Lazy-load every engine, keep near-zero JS on site pages, and don't preload fonts. Size budgets (`scripts/check-budgets.ts`) may be raised, but deliberately, in their own commit, with the reason stated, and after re-measuring on slow 3G.
4. **Git:**
   - Commit in small, verified steps, with no Co-Authored-By or AI attribution trailer.
   - Leave `git status` clean and pushed when you finish.
   - Never delete, move or reformat a file the owner wrote without asking.
5. **Deploys:**
   - Deploy to production only when the owner says "deploy", using `pnpm deploy:cloudflare`.
   - Then run `pnpm build` again to restore the local build.
6. **Accounts and money:**
   - Never type the owner's passwords.
   - Never buy anything or turn on auto-renew.
   - Confirm any outward-facing or irreversible action first.
7. **Content honesty:**
   - Each tool and each real search intent ("compress pdf to 200kb") gets its own URL. No thin pages.
   - Never invent portal or exam specifications. A portal preset is added only after it is verified from an official notice.
   - Every tool verifies its output and reports failures honestly. Never pad a file to reach a size.
8. **Dependencies:** package versions must be at least two weeks old, pinned exactly.
9. **Tone:** legal and marketing copy is plain, diplomatic and protective, without being alarming.

## 3. Architecture

```
apps/site          Astro 7 static site (SEO pages, almost no JS). Embeds each tool in a sandboxed cross-origin iframe.
apps/tool-frame    Preact app on its own origin (niftyfix-frame.prasad9a38.workers.dev): tool UIs, worker pool, strict CSP, no network.
packages/
  tool-sdk         Contracts: defineManifest, defineContent, defineProcessor, CATEGORIES, FILE_FORMATS, errors, output spec
  registry         Lookup, paths, related tools, search (searchRecords), planned.ts (the ~400 planned tools)
  runtime          Worker pool, job runner, file validation, resolveOutputName, downloads, ZIP
  constraints      Target-size quality solver (never pads), crop geometry
  engines/image    Header parsing, decode, resize, encode, verify (pipeline.ts), enhance
  engines/pdf      @cantoo/pdf-lib wrappers: readPdf, finishPdf (re-opens and verifies), selectPages, ...
  ui               Preact components: SingleFileTool, SegmentedControl, PageSelection, OutputSpecForm, ImageResultPanel, CropBox, ...
  portal-specs     Verified portal requirements (none yet)
  analytics-schema Parent and frame message protocol
tools/<category>/<slug>/   One folder per tool (see section 4)
e2e/               Playwright tests (Chromium, Firefox, WebKit, Pixel 7)
fixtures/          Synthetic test files (pnpm fixtures)
scripts/           Generators and CI gates
```

- **Hosting:** Cloudflare Workers static assets on the free plan. `_headers` is generated by `apps/site/src/seo/headers.ts`. The site's CSP allows only Google Tag Manager, Google Analytics and Cloudflare Insights. The tool frame stays closed: no analytics and no network.
- **Analytics:** GTM-NVRZF3S6 (GA4 G-2P60SLY9Q5), loaded only on the niftyfix.in hostname by `apps/site/public/gtm-init.js`.
- **SEO and discovery:**
  - Sitemap at `/sitemap.xml`; AI-crawler summary at `/llms.txt`; site search index at `/search.json`. All three are generated from the registry.
  - Every deploy submits all URLs to IndexNow (Bing and Yandex).
  - Google Search Console is verified by a DNS TXT record.
- **Styling:** Tailwind 4 tokens in `packages/ui/src/theme.css`.
- **Motion:** `apps/site/src/scripts/motion.ts`. It respects reduced motion and uses transforms only.
- **Fonts:** Geist (site only, `font-display: optional`); system fonts in the tool frame.

## 4. How to add a tool

1. **Scaffold** with `pnpm new-tool <category> <slug> "<Tool name>"`.
   - It creates `tools/<category>/<slug>/` and regenerates `tools/registry.generated.ts`.
   - Use the slug already listed in `packages/registry/src/planned.ts`, so the built tool replaces its "coming soon" entry.
   - Slugs follow how people search: `compress-image`, not `image-compressor`.
2. **Write the files**, copying the closest live tool (`tools/pdf/rotate-pdf` is the smallest; `tools/pdf/compress-pdf` shows intent pages):
   - `manifest.ts`: id, slug, category, `status` ('draft', then 'live'), name, h1, tagline, seoTitle, seoDescription (70 to 160 characters), searchAliases, input formats and max bytes, output formats, engine, capabilities, related.
   - `content.ts`: intro, howTo, options, example, limits, faqs, and `variants` (search-intent pages; each has slug, preset, label, h1, SEO fields, intro and faqs).
   - `options.ts`: valibot schema for the options.
   - `processor.ts`: `defineProcessor({ options, run })`. It runs in a worker, reports `progress()`, and returns a verified result (for example via `finishPdf` or the image pipeline's verify).
   - `ui.tsx`: Preact, built from `@niftyfix/ui` components (usually `SingleFileTool`).
   - `preset.ts`: maps variant presets to initial options, when the tool has intent pages.
   - Unit tests (`*.test.ts`) for pure logic.
3. **Reuse engines.** Never add a second pipeline:
   - Image tools use `packages/engines/image` (pipeline, encoders) and `packages/constraints` (target-KB solver).
   - PDF tools use `packages/engines/pdf`.
   - A new heavy engine is a new `packages/engines/<name>`, lazy-loaded inside the processor only.
4. **Write e2e tests** in `e2e/` (see `pdf-tools.spec.ts`, `photo-resizer.spec.ts`). Upload a fixture, process it, download the result, and re-check it in Node. Add axe scans for new layouts in `accessibility.spec.ts`.
5. **Run the gates** before committing:
   ```
   pnpm format && pnpm lint && pnpm check:tools && pnpm check:boundaries && pnpm typecheck && pnpm test && pnpm build && pnpm check:budgets
   pnpm exec playwright test e2e/<your>.spec.ts
   ```
   Then run the full `pnpm e2e` (about 4 minutes locally; about 20 minutes on GitHub CI).
6. **Go live:** set `status: 'live'`, regenerate the registry, and commit. The site picks up the tool page, intent pages, category hub entry, search, sitemap and llms.txt automatically. No site file needs editing.

**Definition of done:** works in all 4 browsers, verifies its output, explains failures, passes axe, stays within budgets, is fast on a phone, its copy has no em dash, and every intent page has real, distinct content.

## 5. Roadmap (what to build next, in order)

The full scope is in `docs/tool-catalogue-v3.md`; the planned list the site reads is `packages/registry/src/planned.ts`.

1. **Wave 1, image tools:**
   - Done (5 Nov 2026): Compress Image (20, 50, 100, 200 KB pages), Resize Image (cm page), Convert Image (6 format-pair pages), Crop Image, Rotate and Flip, Remove EXIF (EXIF viewer and remove-location pages), Watermark Image. All single-file, built on `SingleFileTool` and the shared image pipeline (`sameFormatAs`, `webpOrPng`, `exportImage`, `verifyImageOutput`, `readMetadata`/`stripMetadata`).
   - Next: Passport and Visa Photo Maker, and ID and Photo Sheet Maker (in `forms`).
   - Later: batch mode (many files, ZIP download) as a shared `SingleFileTool` sibling, so every image tool gains it at once. HEIC input needs a decoder (not supported by most browsers).

2. **Indian-script text and OCR:** Devanagari and other scripts in PDF stamps and text tools; Image to Text (OCR) with Indian languages.
3. **Calculators, text tools, developer tools and data tools:** many cheap, fast tools with good long-tail search demand.
4. **Then:** video and audio (ffmpeg.wasm, heavy, lazy), generators (QR Studio, Barcode Studio, Password), archive, and the rest of the catalogue.
